# 진단 및 분석 리포트: fcm-push-quota-guard

- **생성 모드**: 모의 실행 (Dry-run)
- **대상 프로젝트**: `sample-project-id`
- **산출 목적**: 사전 예습, 실습 실행 결과 기록 및 사내 공유/복습용

---

## 1. 진단 실행 콘솔 출력 결과

```text
============================================================================
 [FCM 대량 푸시 쿼터 고갈 및 429 쓰로틀링 복원력 진단 리포트]
============================================================================
진단 대상 프로젝트 ID   : sample-project-id
피크 분당 발송 시도량   : 750,000 건/분
현재 분당 할당량 한도   : 600,000 건/분
할당량 소진율           : 125.0%
추정 429 쓰로틀링 실패율: 20.0%
종합 진단 상태          : ACTION_REQUIRED
----------------------------------------------------------------------------

[항목별 세부 진단 결과]
1. [CRITICAL] DOWNSTREAM_QUOTA_EXCEEDED
   내용: 피크 시 분당 발송량(750,000건)이 기본 할당량(600,000건)을 125.0% 초과하여 약 20.0%의 요청이 429 쓰로틀링 에러로 실패한다.
2. [WARNING] TOKEN_BUCKET_RATE_LIMITING
   내용: 발송 백엔드에 토큰 버킷 속도 제한기(Rate Limiter)가 누락되어 있어 이벤트 발생 시 일시에 요청이 몰려 FCM 인프라 쓰로틀링을 유발한다.
3. [WARNING] EXPONENTIAL_BACKOFF_AND_JITTER
   내용: 429 에러 발생 시 고정 대기 재시도 또는 즉시 재시도로 인해 '재시도 폭풍(Retry Storm)'이 발생하고 있다. Full Jitter 기반 지수 백오프 도입이 시급하다.
4. [INFO] TOPIC_FANOUT_OPTIMIZATION
   내용: 단일 기기 토큰 반복 호출 대신 주제(Topic) 메시징 또는 일괄 발송(send_all) API를 활용하면 네트워크 오버헤드와 쓰로틀링을 대폭 완화할 수 있다.

[복원력 강화 및 긴급 조치 가이드]
1. Google Cloud 콘솔 할당량 상향(Quota Increase) 신청:
   - 콘솔 경로: IAM 및 관리자 > 할당량 및 시스템 한도
   - 대상 지표: Firebase Cloud Messaging API - Downstream messages per minute
   - 권장 신청값: 피크 대비 1.5배 여유 확보 (최소 1,125,000 건/분)
2. 클라이언트/백엔드 토큰 버킷 속도 제한(Rate Limiting) 구현:
   - 발송 큐에서 초당 최대 전송량을 10,000 msg/sec 이하로 스로틀링한다.
3. Full Jitter 지수 백오프 재시도 적용:
   - wait_time = min(max_backoff, base_backoff * (2 ** attempt)) * random.uniform(0.5, 1.5)
============================================================================
```

## 2. 실습 안내 (실제 환경 실행 시 자동 덮어쓰기)

실제 Google Cloud 환경에서 본 진단을 수행하려면 아래 명령어를 실행한다.
실행 결과는 본 `report.md` 파일에 자동으로 갱신(덮어쓰기)된다:

```bash
python diagnose.py
```
