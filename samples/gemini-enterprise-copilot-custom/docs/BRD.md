# Gemini Enterprise 커스텀 에이전트 팩토리 및 Gemini Enterprise app 연동기 비즈니스 요구 사항 명세서 (BRD)

본 문서는 사내 클라우드 아키텍트 및 백엔드 개발자가 사내 데이터베이스, 레거시 시스템 및 외부 API를 결합한 고성능 커스텀(High-code) 에이전트를 신속하게 구축하고, 에이전트 런타임(Agent Runtime)에 배포한 후 제미나이 엔터프라이즈 앱(Gemini Enterprise app)에 외부 에이전트로 원클릭 연동할 수 있도록 지원하는 엔지니어링 도구의 비즈니스 요구 사항 명세서(Business Requirements Document)다.

---

## 1. 추진 배경 및 비즈니스 동기

1. **단순 프롬프트 에이전트의 기술적 한계**:
   - 노코드(No-code) 에이전트는 일반 질의응답이나 검색 그라운딩에 적합하지만, 사내 빅쿼리(BigQuery), 클라우드 SQL(Cloud SQL) 데이터베이스 질의, 사내 기간계 API 호출, MCP(Model Context Protocol) 기반 시스템 연동 등 복잡한 비즈니스 로직을 수행하기에는 기술적 한계가 존재한다.
   - 전문 개발팀이 파이썬(Python) SDK 기반으로 상태 머신, 다단계 추론(Reasoning), 커스텀 툴체인을 직접 코딩할 수 있는 하이코드(High-code) 개발 표준이 필수적이다.

2. **반복적인 인프라 보일러플레이트 작성 부담**:
   - 커스텀 에이전트를 프로덕션에 배포하기 위해서는 Google ADK 연동 코드, 도구 함수 명세, 에이전트 엔진(Agent Engine) 배포 스크립트 등 방대한 인프라 코드를 매번 수작업으로 작성해야 한다.
   - 단 한 줄의 자연어 아키텍처 요구사항으로부터 표준 파이썬 에이전트 코드와 배포 매니페스트를 자동 생성해 주는 개발자 생산성 도구가 요구된다.

3. **Gemini Enterprise app 사내 갤러리 연동의 복잡성 해결**:
   - 에이전트 엔진에 배포된 커스텀 에이전트를 전사 임직원이 사용하는 Gemini Enterprise app 웹 인터페이스에 노출시키려면, 프로젝트 간 IAM 권한 부여, 엔드포인트 바인딩, 조직 정책(Org Policy) 예외 처리가 수반되어 설정 오류가 빈번히 발생한다.
   - 런타임 배포부터 Gemini Enterprise app 사내 갤러리 등록(ADK Agent Binding)까지 전 과정을 자동화하고 연결 상태를 즉시 진단할 수 있어야 한다.

4. **GitHub 저장소 URL 기반 무인 자동 배포 (저장소 연동 자동 배포)**:
   - 개발팀이 CLI나 GCP 콘솔에 직접 접속하지 않고도, Gemini Enterprise app 대화창에서 개발 완료된 GitHub 저장소 주소(`https://github.com/...`)를 입력하는 것만으로 빌드, 배포, 갤러리 등록까지 완결되는 무인 배포 체계를 지원해야 한다.

5. **2단계 고객 온보딩 여정 및 단독 배포 거버넌스 확립**:
   - 실무 고객 관점에서 최초 1회만 개발팀이 `git clone` 후 에이전트 팩토리를 로컬 배포하면, 이후 3대 커스텀 에이전트 및 추가 에이전트 확장은 일반 사용자나 관리자가 GE app 웹 챗창에서 원클릭으로 완결하는 2단계 UX를 제공하여야 한다.
   - 대량 일괄 프로비저닝에 따른 리소스 낭비와 장애 전파를 방지하기 위해 전체 일괄 배포를 배제하고, 3대 핵심 커스텀 추천 질문 칩 기반으로 한 번에 하나씩 독립 배포하는 거버넌스를 정립하여야 한다.

6. **엔터프라이즈 보안성 심의 및 라이프사이클 거버넌스 (Deploy-then-Teardown)**:
   - GitHub 저장소 코드를 Agent Engine 런타임에 직접 패키징하여 전사 배포하는 구조는 사내 CISO 및 정보보호팀의 코드 취약점(취약한 라이브러리, 시크릿 하드코딩) 및 비즈니스 로직 적법성에 대한 엄격한 보안 심의를 요구한다.
   - 따라서 본 도구의 위상을 일반 사원용이 아닌 '사내 IT 관리자(IT Admin) 전용 도구'로 한정하고, 사내 CI/CD 정적 보안 분석(SAST 등) 및 인간 승인(HITL)을 거치도록 하며, 사내 공식 에이전트들의 배포가 완료된 직후에는 공격 표면(Attack Surface) 최소화를 위해 팩토리 자체를 즉시 회수/정리(Teardown)하는 운영 거버넌스를 비즈니스 필수 조건으로 규정하여야 한다.

7. **Day-1 신속 도입과 Day-2 운영 거버넌스의 양립 (Day-1 vs Day-2 Value)**:
   - 엔터프라이즈 AI 도입 과정에서 가장 빈번하게 발생하는 실무 병목은 '초기 프로토타입이나 검증(Day-1)에서는 신속한 가치 실현(Time-to-Value)을 경험하지만, 실제 사내 운영 및 보안 통제(Day-2) 단계로 진입할 때 소스 코드 보안 심의, 코드 취약점 점검, 오탐으로 인한 파이프라인 차단 등 운영 마찰에 부딪혀 전사 프로덕션 확산이 지연되거나 무산되는 현상'이다.
   - 따라서 본 팩토리는 Day-1의 신속한 가치(Fast-path 무정체 즉시 배포)를 기본값으로 온전히 보존하면서도, Day-2의 실무 요건인 코드 취약점 사전 정적 분석(SAST 연동) 및 취약점 발견 시 관리자가 위험을 감수하고 배포를 이어갈 수 있는 인간 개입 승인(Human-In-The-Loop 강제 배포)을 대화형 2단계 가드레일로 제공하여 초기 도입 속도와 지속 가능한 보안 거버넌스를 동시에 달성하여야 한다.

## 2. 핵심 비즈니스 요구 사항 목록 (Business Requirements)

| 요구 사항 ID | 구분 | 핵심 비즈니스 목표 및 요구 명세 |
| :--- | :--- | :--- |
| **BR-01** | 하이코드 에이전트 자동 구축 및 코드 생성 | 개발자의 요구사항(도메인, 데이터 소스, 목적)을 입력받아 즉시 실행 및 커스터마이징 가능한 표준 파이썬 에이전트 코드(`agent.py`)를 자동 생성해야 한다. |
| **BR-02** | 엔터프라이즈 데이터 및 도구 템플릿 | 빅쿼리 SQL 쿼리, 사내 REST API 호출, MCP 도구 연동을 위한 함수 및 OpenAPI 3.0 스키마(`tools.py`)를 표준 규격으로 자동 도출해야 한다. |
| **BR-03** | 에이전트 엔진 런타임 배포 자동화 | 생성된 에이전트를 에이전트 엔진(Agent Engine)에 배포하기 위한 `deploy.py`와 의존성 명세를 완비해야 한다. |
| **BR-04** | GitHub 저장소 직결 무인 배포 (Repo-driven) | 개발자가 대화창에 GitHub 저장소 URL을 제공하면 저장소 구조 검증, 런타임 빌드, 사내 갤러리 자동 등록을 원클릭으로 완결해야 한다. |
| **BR-05** | Gemini Enterprise app 사내 갤러리 원클릭 연동 | 배포된 커스텀 에이전트를 사내 Gemini Enterprise app 포털의 카탈로그에 등록하고 연결성을 사전 검증해야 한다. |
| **BR-06** | 엔터프라이즈 보안 및 격리 준수 | 서비스 계정 최소 권한 원칙(`roles/aiplatform.user`, `roles/discoveryengine.editor`), VPC 서비스 제어(VPC-SC) 보안 경계 고려사항을 설계에 강제해야 한다. |
| **BR-07** | 표준 리소스 라벨링 적용 의무화 | 사내 거버넌스, FinOps 비용 배분 및 자원 추적성을 위해 생성되는 에이전트 서비스 및 관련 리소스에 4대 표준 라벨(`managed-by`, `scenario`, `env`, `created-by`)을 필수로 주입하여야 한다. |
| **BR-08** | 2단계 무인 고객 온보딩 여정 | 개발팀의 로컬 CLI 개입을 최초 1회(`git clone` 후 `python diagnose.py`)로 종결하고, 이후 모든 에이전트 확장 및 배포는 전사 Gemini Enterprise app 웹 챗창에서 무인 완결되어야 한다. |
| **BR-09** | 4대 패밀리 엔터프라이즈 코파일럿 카탈로그 및 0번 레포 직결 배포 | 사내 대표 4대 코파일럿 패밀리(1: 어드민 거버넌스, 2: 노코드 에이전트 팩토리, 3: 데이터 커넥터 스캐폴더, 4: 사내 스킬 팩토리)와 0번(임의 GitHub 저장소 URL 직결 배포) 프리셋을 제공하고, 3개 칩 한도 제약을 극복하는 대화형 카탈로그 조회 도구를 제공해야 한다. |
| **BR-10** | IT 관리자 전용 프레이밍 및 보안 라이프사이클 거버넌스 | 일반 사용자 임의 배포를 방지하기 위해 도구를 IT 관리자 전용으로 한정하고, 배포 전 소스 코드 보안 검증(SAST) 및 로직 승인(HITL) 책임을 명시하며, 공식 에이전트 등록 완료 후 팩토리 자체를 즉시 회수 및 정리(Deploy-then-Teardown)하는 거버넌스 지침을 강제해야 한다. |
| **BR-11** | 선언적 커스텀 레시피 아키텍처 및 케밥 케이스 표준 | 파이썬 코드 수정 없이 커스텀 에이전트를 확장할 수 있도록 선언적 카탈로그 파일(`catalog.yaml`) 분리 구조를 지원하고, 모든 에이전트 슬러그는 `[domain]-[target]-[action]` 형태의 3단계 소문자 케밥 케이스(kebab-case) 표준을 준수하여야 한다. |
| **BR-12** | 에어갭 및 오프라인 환경 회복 탄력성 보장 | 사내 보안 정책상 인터넷 연결이 차단된 에어갭(Air-gapped) 환경이나 외부 카탈로그 엔드포인트 장애 상황에서도 타임아웃(2.0초 이내)을 적용하고 내장된 시드 카탈로그로 원활히 폴백하여 무중단 동작을 보장하여야 한다. |
| **BR-13** | 사전 중복 검증 인터셉터 및 멱등성 보장 | 신규 커스텀 에이전트 등록 요청 시 사내 포털에 이미 등록되어 활성화된 기존 에이전트와의 충돌을 사전에 검증하여 불필요한 빌드와 중복 프로비저닝을 방지하고 기존 에이전트 딥링크를 안내하여야 한다. |
| **BR-14** | Day-1/Day-2 밸런스 2단계 대화형 보안 검증 및 강제 배포 오버라이드 | 저장소 배포 요청 시 기본값은 즉시 배포(Day-1 Fast-path)로 제공하되, 사용자가 원할 경우 빌드 전 정적 보안 정밀 검사(SAST)를 선택할 수 있게 하고, 검사 결과 취약점이나 경고가 발견되더라도 관리자 재량으로 위험을 인지한 상태에서 강제 배포(Force Deploy)를 집행할 수 있는 2단계 대화형 가드레일을 제공하여야 한다. |

## 3. 기대 효과 및 비즈니스 KPI

1. **커스텀 에이전트 개발 및 배포 주기 80% 단축**:
   - 인프라 및 SDK 연동 보일러플레이트 작성 소요 시간(평균 2~3일)을 10분 이내 코드 생성으로 단축한다.
2. **사내 레거시 및 데이터베이스 AI 연결 가속**:
   - 표준화된 도구 템플릿을 통해 빅쿼리 및 사내 기간계 API 등 핵심 기업 자산을 에이전트 도구로 즉시 결합할 수 있다.
3. **개발팀과 현업 사용자의 단일 포털 통합**:
   - 전문 개발팀이 만든 고도화된 백엔드 에이전트를 비개발자 임직원이 매일 쓰는 Gemini Enterprise app 웹 화면에서 바로 호출하여 전사 업무 혁신을 달성한다.
