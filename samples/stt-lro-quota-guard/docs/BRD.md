# 비즈니스 요구 사항 명세서 (BRD): stt-lro-quota-guard

## 1. 프로젝트 개요 및 비즈니스 배경
Cloud Speech-to-Text V2 비동기 배치 음성 인식(`BatchRecognize`) 파이프라인에서 대시보드상 요청 RPM이 정상 한도 내에 있음에도 발생하는 원인 불명의 `429 RESOURCE_EXHAUSTED` 장애를 진단하고, Python SDK 비동기 폴링(`google-api-core`) 지수 백오프 최적화 및 비동기 분리 아키텍처를 처방하는 도구다.

사내 클라우드 운영 환경에서 인프라 담당자와 개발자가 수동 콘솔 점검에 의존할 경우 메트릭 착시 현상으로 인해 장애 원인을 파악하지 못하고 배치 파이프라인이 장시간 마비될 수 있다. 본 미니 프로젝트(`stt-lro-quota-guard`)는 현장 실무에서 즉시 실행 가능한 자동화 진단 및 조치 가이드를 제공하여 운영 안정성을 체계적으로 확보한다.

---

## 2. 비즈니스 요구 사항 목록

### BR-01: LRO 백그라운드 폴링 트래픽 위험도 정밀 산출
- 사내 음성 변환 워크로드의 동시 작업 수(Concurrency)에 따라 발생하는 백그라운드 `GetOperation` 호출량을 시뮬레이션하고, `operation_requests` 쿼터(기본 150 RPM) 소진 위험도를 산출해야 한다.

### BR-02: 대시보드 지표 착시 현상 규명 및 RCA 브리핑
- `BatchRecognize requests` 지표와 `operation_requests` 지표의 분리 구조를 명확히 제시하고, 메트릭 불일치로 인한 장애 원인을 비개발자 및 관리자도 이해할 수 있도록 명료하게 분석 보고해야 한다.

### BR-03: 클라이언트 SDK 코드 레벨 즉각 조치 처방 제공
- 별도의 인프라 증설 없이 즉시 적용 가능한 Python SDK 지수 백오프 커스텀 폴링 코드 스니펫을 터미널과 가이드에 즉시 제시해야 한다.

### BR-04: 엔터프라이즈 비동기 큐 분리 아키텍처 가이드
- 워커 프로세스의 동기식 블로킹 대기를 제거하고 Cloud Tasks/Pub/Sub 기반의 작업 상태 일괄 수집 패턴으로 전환하는 중장기 아키텍처 표준을 제시해야 한다.
