# Gemini Enterprise 어드민 거버넌스 모듈 비즈니스 요구 사항 명세서 (BRD)

본 문서는 사내 IT 어드민 및 클라우드 인프라 운영팀이 제미나이 엔터프라이즈 앱(Gemini Enterprise app) 운영 중 직면하는 9대 핵심 관리 과제(에이전트 및 스킬 스프롤 거버넌스 3종, 사용량 및 텔레메트리 패턴 분석 3종, GE 앱 운영 및 일괄 제어 3종)를 대화형으로 신속 진단하고 해결할 수 있도록 지원하는 사내 어드민 거버넌스 모듈의 비즈니스 요구 사항 명세서(Business Requirements Document)다.

---

## 1. 추진 배경 및 비즈니스 동기

1. **임직원 에이전트 및 스킬 대량 양산(Sprawl)으로 인한 공식 콘솔 거버넌스 한계**:
   - 임직원들이 자율적으로 수백 개의 노코드 에이전트와 업무 도구(스킬)를 등록하면서 공식 구글 클라우드 콘솔의 UI 목록 탐색 및 수동 필터링만으로는 일괄 제어가 번거로운 한계에 직면한다.
   - 60일 이상 호출 0건인 좀비 에이전트 방치, 미검증 외부 엔드포인트를 호출하는 스킬, 퇴사자나 부서 이동자의 고아(Orphan) 에이전트를 식별하고 일괄 정리(`DISABLED`/`ALL_USERS`/`PRIVATE`)할 수 있는 배치 거버넌스가 필요하다.

2. **복잡한 Cloud Logging 검색 부담 없는 직관적 사용량(Usage) 패턴 분석**:
   - 부서별/계정별 토큰 소비량 톱 10 분석, 429 할당량 초과 피크 시간대 추적, 30일 이상 미사용 계정 분석 시 Cloud Logging의 복잡한 LogQL 필터를 매번 작성하고 탐색하는 운영 공수가 크다.
   - 자연어 질의 한 번으로 즉시 실행 가능한 정제된 BigQuery SQL 팩과 로그 라우터 싱크 구성을 제공하여 분석 공수를 줄여야 한다.

3. **GE 앱 운영 현황 조회 및 콘솔 이동 동선 단축**:
   - 등록된 전체 에이전트, 스킬, 연결된 데이터 저장소(Data Store) 현황을 한 번에 조회하고, 필요한 관리 콘솔(Agent Platform, Discovery Engine, BigQuery, Cloud Logging)로 바로 이동하는 딥링크가 필요하다.

4. **단순화된 기본 실행 경로(Zero-Friction Flow)**:
   - 복잡한 분기 질문을 사용자에게 던져 인지 부하를 주지 않고, 입력이 불필요한 영역은 최적의 기본값으로 자동 진행하며, GE App ID 등 선택지가 복수일 때만 번호 선택을 제공하여 사용성을 극대화한다.

## 2. 핵심 비즈니스 요구 사항 목록 (Business Requirements)

| 요구 사항 ID | 구분 | 핵심 비즈니스 목표 및 요구 명세 |
| :--- | :--- | :--- |
| **BR-01** | 9대 GE 어드민 운영 과제 카탈로그 및 자유 프롬프팅 | 대표적인 9대 관리 과제(스프롤 거버넌스 3종, 사용량 패턴 분석 3종, GE 앱 운영 및 일괄 제어 3종) 프리셋을 제공하고, 사용자가 자유 프롬프트(`--prompt`)로 원하는 관리 이슈를 질의할 수 있어야 한다. |
| **BR-02** | 에이전트 및 데이터 저장소 통합 현황 조회 | 사내 GE App에 등록된 전체 에이전트/스킬 목록과 연결된 데이터 저장소(Data Store) 바인딩 현황을 실시간 조회해 표로 반환해야 한다. |
| **BR-03** | 활성 사용자 및 30일 미사용 계정 분석 SQL | 부서별 활성 사용자(DAU/MAU) 지표를 분석하고 30일 이상 미사용 계정을 식별하는 BigQuery SQL을 제공해야 한다. |
| **BR-04** | 토큰 소비 톱 10 및 429 쓰로틀링 역추적 SQL | 부서별/계정별 토큰 소비 톱 10 집계 및 429 할당량 초과 에러 발생 시간대 역추적 BigQuery SQL 팩을 제공해야 한다. |
| **BR-05** | 에이전트 배치 상태/공유 범위 제어 및 삭제 | 테스트/방치 에이전트를 키워드, 상태, 공유 범위로 필터링하고 일괄 비활성화(`DISABLED`), 공유 범위 변경(`ALL_USERS`/`PRIVATE`), 정리 삭제를 수행할 수 있어야 한다. |
| **BR-06** | 에이전트 및 스킬 스프롤 전수 감사 | 60일 미사용 좀비 에이전트, 비표준 외부 엔드포인트 스킬, 고아 에이전트 소유권 이관을 지원하는 거버넌스 가이드를 제공해야 한다. |
| **BR-07** | 원클릭 로그 싱크 및 콘솔 딥링크 | Cloud Logging 감사 로그를 BigQuery로 라우팅하는 로그 싱크 구성 스크립트와 GCP 콘솔 GE Admin 딥링크를 안내해야 한다. |
| **BR-08** | 대화형 추천 후속 질문 및 표준 리포트 | 단계별 조치를 위한 마크다운 추천 후속 질문을 출력하고 `report.md` 표준 보고서를 덮어써야 한다. |
| **BR-09** | 표준 리소스 라벨링 적용 의무화 | 사내 거버넌스, FinOps 비용 배분 및 자원 추적성을 위해 리소스 생성 시 4대 표준 라벨(`managed-by`, `scenario`, `env`, `created-by`)을 필수로 주입하여야 한다. |
| **BR-10** | 선언적 어드민 레시피 아키텍처 및 케밥 케이스 표준 | 파이썬 코드 수정 없이 관리 과제를 확장할 수 있도록 선언적 카탈로그 파일(`catalog.yaml`) 분리 구조를 지원하고, 모든 과제 슬러그는 `[domain]-[target]-[action]` 형태의 3단계 소문자 케밥 케이스(kebab-case) 표준을 준수하여야 한다. |
| **BR-11** | 에어갭 및 오프라인 환경 회복 탄력성 확보 | 외부 카탈로그 엔드포인트 연결 장애 상황에서도 타임아웃(2.0초 이내)을 적용하고 내장된 시드 카탈로그로 원활히 폴백하여 안정적인 동작을 유지하여야 한다. |
| **BR-12** | 사전 슬러그 및 명칭 중복 검증 인터셉터 | 신규 관리 과제 추가 시 기존 과제와의 슬러그, 디스플레이 이름 충돌 여부를 사전에 검증하여 설정 충돌 사고를 예방하여야 한다. |

## 3. 기대 효과 및 비즈니스 KPI

1. **어드민 운영 문의 대응 시간 80% 단축**: 9대 핵심 관리 이슈 및 배치 제어 도구 연동으로 어드민 작업 시간을 대폭 절감한다.
2. **유휴/테스트 에이전트 정리 효율화**: 사내 갤러리에 누적된 미사용 및 테스트 에이전트를 신속하게 식별 및 비활성화하여 목록 가독성과 운영 품질을 유지한다.
3. **감사 로그 분석 및 로그 싱크 구성 공수 절감**: 수동 콘솔 검색 및 Cloud Logging 쿼리 작성 시간을 95% 단축한다.
